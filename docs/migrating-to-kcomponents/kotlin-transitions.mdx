This page shows how to convert Spec transitions (`@OnCreateTransition` and `@OnUpdateStateWithTransition`) to the Kotlin animation APIs. Most conversions use one of three APIs from `com.facebook.litho.animation`:

- [`Style.transition { }`](../transitions/style-transitions.mdx) animates a component's properties, position or size whenever they change between renders.
- [`useAnimationGroup`](../transitions/state-based-animations.mdx) animates values derived from a state, and can pick a different animation depending on the state you're coming from.
- [`AnimatedVisibility`](../transitions/animated-containers.mdx) animates content as it's added or removed.

These APIs are marked `@ExperimentalLithoApi`, so add `@OptIn(ExperimentalLithoApi::class)` to the component. If your code already uses `useTransition`, see [Migrating from Transitions](../transitions/migrating-from-transitions.mdx) instead.

## How the Kotlin APIs differ

- **No transition keys.** In the Spec API, `@OnCreateTransition` returns a `Transition`, and Litho matches it to components through transition keys. In Kotlin, you add `Style.transition { }` to the component that should animate. If that component can move around, for example in a list, give it a stable `key(...)` so Litho recognizes it from one render to the next.
- **Only changes animate.** `Style.transition` animates a property only when its value changes, so you don't need `Diff<T>` to check whether something changed.
- **Previous and next values come from `useAnimationGroup`.** When the animation depends on what the value was before, `useAnimationGroup` gives its `transitionSpec` both the previous state (`initialState`) and the new one (`targetState`).
- **Different default motion.** A Spec transition with no animator springs with overshoot, while `spring()` doesn't overshoot. `Transition.timing` eases differently from `tween()`. To keep the existing motion, use `compatSpring()` or `compatTiming(durationMs)`. [Animators](../transitions/migrating-from-transitions.mdx#animators) maps each legacy animator to its spec. The examples on this page use `spring()` and `tween()` for brevity.

| Spec API | Kotlin API |
| :-- | :-- |
| `@OnCreateTransition` that animates a property, position or size | `Style.transition { }` on that component |
| `Transition.allLayout()` | `bounds` in `Style.transition { }` on each component that should animate |
| `.animator(...)` | The matching compat spec, such as `compatSpring()` or `compatTiming(durationMs)`. See [Animators](../transitions/migrating-from-transitions.mdx#animators) |
| `Transition.sequence`, `stagger` or `delay` | A delay on each component's spec, such as `tween(200.ms, delay = 100.ms)` |
| `Diff<T>` to check whether a value changed | Not needed: `Style.transition` only animates changes |
| `Diff<T>` to choose an animation from the previous and next value | `useAnimationGroup`, whose `transitionSpec` receives `initialState` and `targetState` |
| `@OnUpdateStateWithTransition` | Update the state as usual; `Style.transition` or `useAnimationGroup` animates the change |
| `appearFrom` / `disappearTo` | `AnimatedVisibility` |
| `transitionEndHandler` | The `onSettled` parameter of `useAnimationGroup` or `useAnimatedFloat` (and the other `useAnimated*` hooks) |
| `TransitionKeyType.GLOBAL`, or a transition key whose component lives elsewhere | No direct equivalent yet. Move the transition onto the component that should animate |

## Scenarios

### Simple transition without parameters

<table>
<tr>
<th>Spec API</th>
<th>Kotlin API</th>
</tr>
<tr><td>

```kotlin
@OnCreateTransition
fun createTransition(c: ComponentContext): Transition {
  return Transition.allLayout()
}
```
</td><td>

```kotlin
Column(style = Style.height(height).transition { bounds = spring() })
```
</td></tr>
</table>

`bounds` animates the component's position and size. Add it to each component that should animate. Components without their own `Style.transition` jump to their final positions. If they should follow the animated size frame by frame, use `bounds(spring(), reflow = true)`. That recalculates the layout on every frame, so only use it where you need it.

### Transition depends on the current value

Choose the animation spec from the value. `snap()` applies the change without animating it.

<table>
<tr>
<th>Spec API</th>
<th>Kotlin API</th>
</tr>
<tr><td>

```kotlin
@OnCreateTransition
fun createTransition(
  c: ComponentContext,
  @State someEnum: EnumType
): Transition? {
  return when (someEnum) {
    EnumType.VALUE_1 -> Transition.create(...)
    EnumType.VALUE_2 -> Transition.create(...)
    else -> null
  }
}
```
</td><td>

```kotlin
Style.transition {
  bounds = when (someEnum) {
    EnumType.VALUE_1 -> spring()
    EnumType.VALUE_2 -> tween(300.ms)
    else -> snap()
  }
}
```
</td></tr>
</table>

### Transition only when a value changed

`Style.transition` only animates a property whose value changed, so you can drop the check.

<table>
<tr>
<th>Spec API</th>
<th>Kotlin API</th>
</tr>
<tr><td>

```kotlin
@OnCreateTransition
fun createTransition(
  c: ComponentContext,
  @State isEnabled: Diff<Boolean>
): Transition? {
  return if (isEnabled.previous != isEnabled.next) {
    Transition.allLayout()
  } else {
    null
  }
}
```
</td><td>

```kotlin
Column(
    style =
        Style.height(if (isEnabled) 120.dp else 48.dp)
            .transition { bounds = spring() })
```
</td></tr>
</table>

There's one difference to check. The Spec version only animated renders where `isEnabled` changed. `Style.transition` animates the height whenever it changes, whatever the cause. If something else can change the height and that change shouldn't animate, use `useAnimationGroup` with `isEnabled` as its state, as in the next scenario.

### Transition depends on the previous and next value

Use `useAnimationGroup` with the state as its target. Its `transitionSpec` runs with the previous state as `initialState` and the new state as `targetState`. `A isTransitioningTo B` is shorthand for `initialState == A && targetState == B`.

<table>
<tr>
<th>Spec API</th>
<th>Kotlin API</th>
</tr>
<tr><td>

```kotlin
@OnCreateTransition
fun onCreateTransition(
  c: ComponentContext,
  @State visibility: Diff<Visibility>
): Transition {
  return when {
    visibility.previous == INVISIBLE -> ...
    visibility.next == INVISIBLE -> ...
    visibility.previous == PARTLY_VISIBLE &&
      visibility.next == VISIBLE -> ...
    else -> ...
  }
}
```
</td><td>

```kotlin
val group = useAnimationGroup(visibility)
val alpha =
    group.animateFloat(
        transitionSpec = {
          when {
            initialState == INVISIBLE -> tween(150.ms)
            targetState == INVISIBLE -> tween(300.ms)
            PARTLY_VISIBLE isTransitioningTo VISIBLE ->
                spring(dampingRatio = DampingRatio.MediumBouncy)
            else -> spring()
          }
        },
    ) { state -> alphaFor(state) }

Row(style = Style.alpha(alpha))
```
</td></tr>
</table>

If only one value animates and its spec doesn't depend on the previous state, `useAnimatedFloat` (or another `useAnimated*` hook) is simpler: `val alpha = useAnimatedFloat(alphaFor(visibility), tween(300.ms))`.

If the component already animates through `Style.transition` and only the spec depends on the direction, you can keep `Style.transition`: record the state you're leaving when you update it, and choose the spec from both values. ### Updating state with a transition

`@OnUpdateStateWithTransition` attached a transition to one particular state update. In Kotlin, update the state as usual. The component declares how the property animates, so the change animates whichever update caused it. If other updates to the same property shouldn't animate, see [Transition only when a value changed](#transition-only-when-a-value-changed).

<table>
<tr>
<th>Spec API</th>
<th>Kotlin API</th>
</tr>
<tr><td>

```kotlin
@OnEvent(ClickEvent::class)
fun onClick(c: ComponentContext) {
  SomeComponent.onUpdateShiftWithTransition(c, newShiftValue)
}

@OnUpdateStateWithTransition
fun onUpdateShift(
  shiftPx: StateValue<Int>,
  newShiftValue: Int
): Transition {
  shiftPx.set(newShiftValue)
  return Transition.create(SHIFT_TRANSITION_KEY)
    .animate(AnimatedProperties.Y)
}
```
</td><td>

```kotlin
val shift = useState { 0.dp }
...
Column(
    style =
        Style.margin(top = shift.value)
            .transition { y = spring() }
            .onClick { shift.update(newShift) })
```
</td></tr>
</table>

### Running code when a transition ends

Replace `transitionEndHandler` with the `onSettled` parameter of `useAnimationGroup`. It runs once every animation in the group has finished, and receives the state the group settled on.

```kotlin
val group =
    useAnimationGroup(expanded, onSettled = { settledState -> onExpandFinished(settledState) })
val height = group.animateDimen { state -> if (state) 200.dp else 56.dp }
```

For a single value, `useAnimatedFloat` and the other `useAnimated*` hooks take the same `onSettled` parameter. `Style.transition` doesn't have an end callback yet. If you need one, animate that value with `useAnimationGroup` or a `useAnimated*` hook instead.

### Appear and disappear

Wrap content that used `appearFrom` or `disappearTo` in an [`AnimatedVisibility`](../transitions/animated-containers.mdx) instead of adding and removing it conditionally:

```kotlin
child(
    AnimatedVisibility(
        visible = shown,
        enter = fadeIn() + expandVertically(),
        exit = fadeOut() + shrinkVertically(),
    ) {
      Row(style = Style.width(80.dp).height(80.dp))
    })
```

[Migrating from Transitions](../transitions/migrating-from-transitions.mdx#appear-and-disappear) lists the enter and exit animation for each property.
