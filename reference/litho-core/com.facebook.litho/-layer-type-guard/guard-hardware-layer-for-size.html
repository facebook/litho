guardHardwareLayerForSize

@JvmStatic
fun guardHardwareLayerForSize(view: View, requested: Int): Int

Returns requested unchanged, except a LayerType.LAYER_TYPE_HARDWARE request for a view whose width or height exceeds maxHardwareLayerSizePx (when that is set > 0) is downgraded to LayerType.LAYER_TYPE_NONE, to avoid the uncatchable hwui "Unable to create layer" native abort on views larger than the GPU's GL_MAX_TEXTURE_SIZE.

NONE — not SOFTWARE — is used on downgrade: a software layer allocates a Bitmap of the view size (e.g. ~71MB for 1088x16384), trading the abort for an OOM. NONE allocates nothing and renders directly; the only cost is that a grouped layer paint (alpha/color filter) is applied per-primitive instead of as a group, which is negligible for an over-max-size view.
